# Full-parity acceptance for the one-JAR build

The target is **one installable JAR for Minecraft 1.21.1 / NeoForge 21.1.267**, containing both exact Minechem releases and the requested Voltz and GeoStrata systems. Booting the game, remapping class names, or passing a subset of GameTests is not full parity. The current build still requires `--allow-preview-ports` and reports `parity_verified: false`.

Use the pinned binaries in `mcmodup/legacy_testbed.py` as the reference, including CalclaviaCore from Voltz Server 3.0.0c. Later releases, wiki descriptions, and a class-name inventory are not substitutes for running the exact versions. The two Minechems must also work together without accidentally mixing recipes, item metadata, saved inventories, research, or power behavior.

**Scope:** Gameplay parity is evaluated in fresh Minecraft 1.21.1 worlds. Saving and reloading those worlds and items is still tested. Importing or migrating pre-1.21.1 saves is out of scope.

The native build uses deliberate substitutions at some boundaries. For example, .394 has a paired-only recipe variant where the two legacy recipes have identical inputs, reactors use FE where the original used RF, and projectors are not allowed to overwrite an occupied core site. Record such differences even if the alternative is more convenient. They aren't evidence that the original behavior was reproduced.

## Verified Minechem feature slice: FINAL synthesizer

The [exact Forge runtime replay](https://github.com/mechwarriorpro/mcmodup/actions/runs/44492887452/job/135452699147) re-observed **301 ordered registrations**: 278 successfully paid canonical patterns, 22 patterns that selected an earlier registration, and one recipe beyond the machine's 1,022,220-unit buffer. The machine accepted up to 200 units per receive. The ghost grid, not storage, selected the recipe. Shaped recipes checked the declared positions and accepted excess amounts; shapeless recipes required exact stack counts. For example, the seven-stone preview cost 500 per withdrawal unit by regular click, but 500 per seven-stone batch by shift-click. The iron recipe paid at exactly 10,000, drawing 16 iron tubes across storage slots. The probe checked the survival crafting chain, left/right/shift-clicks, and journal selection, removal and reload. It also toggled the original automation gate and checked all six faces. The separate legacy extraction helper delivered a full seven-stone batch even when asked for one item; the native sided capability honors the requested amount.

The native implementation keeps these recipes in the original order and tests the canonical winner, exact charge and paid output. It uses the original GUI texture and coordinates, but NeoForge FE and native menu controls replace UE and the original tabs. It refreshes edited ghosts immediately, prevents inserts into the virtual result, and stops bulk crafting before paying for a batch that will not fit. The Polytool row produces the [native upgradeable tool](legacy-testbed.md#minechem-polytool). The emerald-block row remains over capacity, as in the original. This does not establish arbitrary add-on recipes or every configuration-dependent outcome. See the [playable workflow](legacy-testbed.md#minechem-final-synthesizer); older timed-preview synthesizer data is not migrated.

## Verified Minechem feature slice: material rules and treatments

The [pinned original probes](https://github.com/mechwarriorpro/mcmodup/actions/runs/44501155365) confirm 347 reproducible FINAL material observations, 147 drink outcomes, and 23 molecules eligible for food spiking; .394 registered 866 materials (including optional items and fluids), 52 pharmacology profiles and 399 synthesis recipes. Several old identifiers don't have a verified modern item mapping. The `.394` torch's recursive coal/charcoal ingredient can vary at boot; the port freezes the observed charcoal variant. The native material table declares example yields and rolls on intake rather than turning an example into a guaranteed output.

Original .394 regular clicks return a complete batch; shift-click can craft multiple batches, including some that the old menu paid for and then lost when actual player inventory was full. The native menu preflights capacity. The shared pattern for leucine and isoleucine is resolved with an explicit saved selection instead of boot-dependent ordering. NeoForge automation honors extraction limits rather than handing out a larger stack.

Treatments preserve native item components. FINAL spiked food replaces a dose; .394 appends and has release-local switches for food, swords and optional molecule profiles. The native menu requires exactly a base item plus one tube, refuses cross-release treatments, and caps dose lists. Damage and food completion use NeoForge hooks; Delirium uses a native HUD layer. Radiation and fluid contact are separate from the treatment rules below. The legacy energy and configuration systems are not ported. See [the testbed verification and current limits](legacy-testbed.md#verified-build).

## Verified Minechem feature slice: Polytool

The [pinned original replays](https://github.com/mechwarriorpro/mcmodup/actions/runs/44507443391) clicked the original infusion slots, checked NBT after reload, surveyed 15 alloy profiles against 12 vanilla block samples, and exercised mining and melee. A full stack of 64 accepted tubes installs one rank; a short stack or unsupported item is refused. Right-clicking with a full stack could leave one unpaid tube in the original slot. A rejected alloy could leave all 64 there. FINAL stores element ordinals (e.g. 12 for Aluminium); .394 stores atomic numbers (13). The native menu leaves any rejected payment in the cursor or inventory and binds to the original held stack. It syncs release-local item components instead of replaying the old GUI update packets.

Both originals report speed 8 without alloys. Aluminium gives log/ore/dirt speeds 16/4/4; the second stack and an Aluminium→Gallium combination were rejected. Three Vanadium batches fit, but a fourth is rejected. Blade alloys affect .394's sword stat but not cobweb speed. FINAL derives the stat from cobweb speed, which stays 8 in the pinned environment. The native tool uses measured stats with modern tool tags, normal cooldowns and one melee damage path. It uses 8 base player damage for FINAL (the legacy hit callback's value) and .394's measured item modifier, which adds to the player's base damage.

One Iron infusion mined the neighboring coal ore but not the next block in the chain. Two Oxygen ranks changed 100 air to 102, and Sulfur ignited the melee target. Neither hook wore down the tool. The native ore path respects modern player break handling and an iron-tier harvest check and doesn't replay the legacy Carbon drop bonus; Oxygen caps at the native maximum air.

FINAL accepted 49 elements. Its UE API reported acceptance even without Lithium. At rank two, `recharge(..., true)` left charge unchanged, and `recharge(..., false)` wrote 200 for a transfer of 100; the saved long caused the original integer read and next write to throw. Discharge and set were stubs. The working native receive-only FE adapter preserves rank scaling and the intended logarithmic bonus, with normal simulation semantics and saturation. .394 accepted 48 elements, with no Lithium infusion or Polytool energy interface.

**Still absent:** The effects associated with H, He, Be, B, C, N, F, Ne, Na, Mg, Si, P, Cl, Ar, Ca, Ti, Cr, Ni, Zn, Br, Kr, Rb, Ag, Cs, Pt, Au, Hg, Pb, Fr and U. Their ranks can be stored, but their special combat, drop, world, inventory and tick effects don't fire. There is no UE/CoFH item-power compatibility, original orbit animation, or reference-client visual parity. The [playable instructions](legacy-testbed.md#minechem-polytool) describe the supported paths.

## Minechem feature slice: fluids, decay, and storage

The [original Forge replays](https://github.com/mechwarriorpro/mcmodup/actions/runs/44513456124) measured FINAL's 260 chemical fluid registrations, .394's 285 placeable chemical fluids, and their different handling in the decomposer. FINAL accepts local non-water fluids, but never drains or processes them and doesn't persist them. Its vanilla-water path still uses the strict thresholds and converted-input save. .394 keeps a single persistent 5,000 mB tank: a 124 mB iron fill doesn't start the batch, and adding 2 mB spends 1,000 at intake, leaving 1 mB and one tube to emit. Vanilla water and lava have their own recipes; there is no duplicate .394 water fluid.

In .394 a tube is 125 mB and a bucket is 1,000 mB. The original water bucket reverses to eight tubes, but eight water tubes cannot craft it. The two declarations named `mt` both read the Meitnerium tube fluid recipe. Only the element bucket returns a decomposition lookup; [the original has produced two different yields for that bucket](https://github.com/mechwarriorpro/mcmodup/actions/runs/44512796171/job/135521039967). The native registry gives the two declarations distinct IDs, uses the observed Meitnerium variant for the element bucket, and does not invent a decomposition recipe for the molecule bucket. FINAL molecule tints can change when the old game starts; the preview keeps a recorded palette.

Uranium decay differs between the releases: FINAL changes to protactinium at the lifetime boundary, and can catch up more than one step. .394 waits until after the boundary, and advances one step per update; its default lifetime is 20% of the base table. Both leaded chests have nine 64-item slots; FINAL also has a 27-slot cabinet and the cabinet-to-chest recipe. The native build saves clocks on stacks and .394 radioactive sources. A source exchange costs eight matching tubes, and their oldest clock follows the mixed fluid or its container.

### Decay in player and machine inventories

The pinned [FINAL](https://github.com/mechwarriorpro/mcmodup/actions/runs/44523695350/job/135558590767) and [.394](https://github.com/mechwarriorpro/mcmodup/actions/runs/44523695350/job/135558591226) survival probes re-observed **28 and 43 rows** respectively, including health and outbound warnings. Three overdue uranium tubes become three protactinium tubes: FINAL deals one damage point and reports the two elements; .394 deals three and includes the elapsed time. Both use generic damage, bypassing ordinary armor. Neither original registered a radiation-shielding item in the tested pack, despite containing an armor class. FINAL schedules the scan every 20 ticks; .394 scans at the start of each server player tick. A carried cursor stack isn't scanned until it returns to a slot.

A synthesizer or fission screen reduces player decay damage by 40% before rounding; a fusion screen prevents the damage but still warns. FINAL's first 27 menu slots included 7 player slots in the synthesizer, 17 in the decomposer, and 18 in the leaded chest. The preview keeps those slot boundaries. .394 only shields the actual synthesis and leaded storage slots. In its decomposer, `decaySafeMachines=false` pauses the machine slots, while `true` (the original's loaded default) lets them age during the open menu scan. Both values retain the 40% player damage reduction. Virtual recipes are not treated as paid inventory.

The .394 element bucket resets its clock without changing the chemical. Molecule buckets retain one daughter in bucket form and return the other tubes; the original's cached product order could select either daughter. The native preview chooses deterministically: one radium chloride bucket yields two chlorine buckets and eight francium tubes, and one francium hydroxide bucket yields one radon bucket and eight hydroxide tubes. Filled buckets stay limited to one per slot, and byproducts that won't fit are dropped. Warnings show localized bucket names instead of the original's `null`, and overdue durations don't turn blank after a day. This is a native adaptation, not a port of the legacy event API.

### .394 fluid automation and reactions

The [exact .394 Forge replay](https://github.com/mechwarriorpro/mcmodup/actions/runs/44518971853/job/135542326863) matched 56 observations for dispensing, block and item contact, ignition, propagation and furnace fuels. In the original, a filled element stack tried to collect instead of pour, and empty tubes could destroy the target water and throw. The molecule dispenser combined a 3+5 payment, but on 3+4 it erased the selected three tubes and the target flow. An empty bucket could collect a full bucket from either a source or a flowing cell. The native dispenser uses filled tubes to pour and empty tubes to collect, verifies all eight matching tubes before spending, requires a source to collect, and keeps the previous empty-bucket behavior for other targets. A filled .394 bucket will not displace an occupied target. Radioactive source clocks survive collection, including the bucket stack's full item components.

The trace contains **13 unordered contact pairs**, separate default-on settings for block and dropped-bucket contact, and a separate in-game TNT fluid ignition rule (lava or fire). Block contact consumes both inputs. Dropped-bucket contact requires the item's bounding box to touch vanilla water and uses the block at the item's center to look up the reagent. A bucket in a pure chemical pool does not react, but it can react at a water boundary. A successful item reaction consumes the filled bucket and returns an empty one without deliberately removing the target pool. The representative source reaction places gas above and solid below; with a flowing input, it produces flowing gas and no solid. The original water product has no placeable Minechem block; the preview preserves that omission when there is a free output cell. It does not overwrite unrelated blocks when choosing product positions.

The original block updates sent gas up, liquid down, and left one-quanta solids stationary. The native preview follows those directions and the recorded viscosity delays, with seven-quanta first flow cells, lateral flow when capped, and no new sources from flow. It protects occupied cells and clears unsupported flow rather than letting it generate a new column. The **[14 measured tube fuels](../mcmodup/templates/minechem/release394-fluid-automation.txt)** include 100 ticks for hydrogen, 200 for carbon, and 1,100 for ethanol. No chemical bucket returned a positive burn time. Neither the dispenser registration nor the fuel and reaction tables are applied to FINAL.

**Still incomplete:** exact original displacement, random tick timing, rendering, and interaction with third-party fluids; remaining radiation callbacks, world interactions, and hazard presentation; legacy integrations. See the [walkthrough](legacy-testbed.md#minechem-fluids-and-storage) and [packaged tests](legacy-testbed.md#verified-build).

## Minechem uranium generation

The checksum-pinned [FINAL](https://github.com/mechwarriorpro/mcmodup/actions/runs/44528608461/job/135575680942) and [.394](https://github.com/mechwarriorpro/mcmodup/actions/runs/44528608461/job/135575681514) Forge runs each matched **12 observations**, including the registered Forge chunk seed, the order of random draws, and placed block coordinates in controlled stone chunks. Both made six attempts by default (`uraniumOreDensity + 1`), with X/Z sampled in the chunk, a Y origin of **0–49**, and a per-attempt size roll from **0 through 12** (`uraniumOreClusterSize + 9`). A zero-size attempt still advanced the stream. The vein center was offset by eight blocks in X/Z, and veins could cross into a neighbouring chunk. For the recorded seed and chunk, both releases placed **29 blocks** on all stone and **11** with a mix of stone, ore, dirt, gravel and air. The Nether and End attempted no placements.

The native feature replays those draws and the ellipsoid placement on 1.21.1 stone, retaining the Y=0 floor and leaving granite, deepslate and existing ore alone. Six attempts does not mean six visible veins. The native [worldgen settings](legacy-testbed.md#minechem-uranium-in-new-worlds) are independent per release and affect newly generated chunks. In a standalone build the seed follows Forge; with both releases installed, .394 uses `worldSeed ^ 0x394` so the two releases do not roll identical sets of stone targets. Overworld-type biome selection and modern generation order and terrain still differ from the old games. The same seed does not imply the same ore map in normal terrain across Minecraft versions. The [staged JAR tests](https://github.com/mechwarriorpro/mcmodup/actions/runs/44528608436/job/135575680484) matched the fixture coordinates and generated both ores together in fresh stone chunks. Third-party ore replacement and OreDictionary crafting/decomposition were not tested in this slice.

## Evidence required for a release claim

1. **Original runtime:** Record what the exact binary registers and what players can do with it on Forge: recipes and progression, machine reactions and gates, faces, save/reload, failure states and client interactions. Check configuration-dependent paths as well as defaults.
2. **Native comparison:** Replay those cases on NeoForge and assert the observable outputs and side effects. A synthetic happy path alone is not enough. A behavior that was intentionally changed must be identified, not counted as an exact match.
3. **Single-JAR integration:** Run the cases against the packaged JAR, not just the projects used to build it. Load both Minechems, exercise cross-system interactions, and verify clean dedicated-server and graphical-client runs, including usable screens, world reloads and resource reloads. Tie the result to the tested artifact's SHA-256.
4. **Integration:** Verify each claimed integration with the supported native dependencies. Do not infer compatibility with original add-on JARs or arbitrary third-party packs from a fresh-world boot. Legacy save migration is not a release gate.

See the [install and gameplay guide](legacy-testbed.md) for the bounded preview and links to the actual verification runs. Keep derivatives private unless redistribution rights for the exact inputs have been established.
